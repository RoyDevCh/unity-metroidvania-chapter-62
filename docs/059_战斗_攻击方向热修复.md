# 攻击方向热修复

> **战斗** | 第 59/192 节 | [[058_战斗_受击冲击|⬅️ 受击冲击]] | [[060_战斗_反击与眩晕|➡️ 反击与眩晕]]

## 🎯 本节目标
解决在执行攻击动作时，角色偶尔会出现攻击方向与移动方向相反（例如向右跑却向左攻击）的 Bug，确保攻击方向的判定逻辑准确无误。

## 🖥️ 操作步骤

### 1. 定位问题与调试
在战斗系统中，攻击方向通常依赖于 `X input`。当出现方向错误时，可以通过 `Debug.Log` 实时监测输入值。

- 打开负责处理攻击状态的脚本。
- 在处理攻击方向的逻辑处添加 `Debug.Log(xInput)`。
- 运行游戏并开启 Debug 模式，观察在向右移动（`facing direction` 为 1）并攻击时，`xInput` 是否意外变成了 -1。

![定位问题](../screenshots/059_new1.jpg)

### 2. 分析原因
通过调试发现，在进入攻击状态（Enter State）时，`xInput` 有时会保留上一次 `Update` 循环中其他状态的残留值。这导致在执行攻击方向判定时，程序错误地应用了之前的输入方向，从而导致角色向反方向攻击。

![分析原因](../screenshots/059_new2.jpg)

### 3. 实施修复方案
为了消除状态切换时的输入残留，我们需要在攻击状态的 `Enter` 方法中显式地将 `xInput` 重置为 0。

- 找到攻击状态机的 `Enter` 方法。
- 添加一行代码 `xInput = 0;`。
- 添加注释以记录此修复目的。

![修复代码](../screenshots/059_new3.jpg)

## 💻 完整代码

修复本身只有一行——在玩家攻击状态的 `Enter()` 中把水平输入冻结为 0：

```csharp
// 玩家攻击状态（PlayerAttackState）
public override void Enter()
{
    base.Enter();

    // We need this to fix bug on attack direction
    // 冻结水平输入，防止攻击瞬间朝向翻转
    xInput = 0;
}
```

> 🔑 进入攻击状态的瞬间输入可能还残留着上一状态 `Update` 里读到的值（例如向右跑时残留 `-1`），`facingDir` 据此翻转就会导致朝反方向攻击。在 `Enter()` 里强制 `xInput = 0`，攻击期间不读水平输入，朝向就不会在出手瞬间翻转。

## 📝 核心要点

- **Bug 现象**：角色在向一个方向移动并攻击时，随机出现向反方向攻击的情况。
- **根本原因**：进入攻击状态（`Enter`）时，成员变量 `xInput` 缓存了前一个状态 `Update` 中的输入值，朝向判定据此翻转导致反向攻击。
- **解决方案**：在攻击状态的 `Enter()` 中将 `xInput = 0` 冻结水平输入，防止攻击瞬间朝向翻转——一行代码的热修复。
- **调试技巧**：对 `xInput` 加 `Debug.Log`，同时打开 Inspector 的 Debug 模式，对照 `Facing Direction` 与 `xInput` 的值快速定位逻辑矛盾点。
