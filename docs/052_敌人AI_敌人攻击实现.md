# 敌人攻击实现

> **敌人AI** | 第 52/192 节 | [[051_敌人AI_敌人战斗状态|⬅️ 敌人战斗状态]] | [[053_敌人AI_战斗状态完善|➡️ 战斗状态完善]]

## 🎯 本节目标
为骷髅敌人（Skeleton Enemy）实现完整的攻击状态机逻辑，包括创建攻击动画、编写状态类、处理状态切换以及通过动画触发器（Animation Triggers）实现攻击动作的自动结束。

## 🖥️ 操作步骤

### 1. 创建攻击动画
首先需要为骷髅敌人准备攻击动作的动画剪辑。
1. 打开 **Animator** 窗口，点击 `Add Animation` $\rightarrow$ `Create New Clip`。
2. 保存路径为：`animation/animations/skeleton/skeleton attack`。
3. 在 `graphics` 文件夹中找到骷髅的攻击帧，将所有帧拖入时间轴。
4. 为了让攻击动作更迅捷，将帧间隔（Sample Rate/Interval）设置为 **15 帧**。

![创建动画](../screenshots/052_new1.jpg)

### 2. 配置 Animator 参数与转换
在 Animator 控制器中设置状态切换逻辑：
1. 创建一个名为 `attack` 的 **Boolean** 参数。
2. 创建从 `Any State`（或当前状态）到 `Skeleton Attack` 的 Transition，条件设为 `attack = true`。
3. 创建从 `Skeleton Attack` 到 `Exit` 的 Transition：
   - 条件：`attack = false`。
   - 勾选 `Has Exit Time`。
   - 将 `Transition Duration` 设为 `0`。

![Animator配置](../screenshots/052_3.jpg)

### 3. 编写 SkeletonAttackState 类
创建 `SkeletonAttackState.cs` 脚本，继承自 `EnemyState`。

- **构造函数**：与其他状态统一使用**三参构造** `(Enemy _enemy, EnemyStateMachine _stateMachine, string _animBoolName)`，并通过 `base(_enemy, _stateMachine, _animBoolName)` 透传给父类（替换旧的仅传入敌人的单参构造）。
- **核心逻辑**：在 `Update` 中调用 `skeleton.SetZeroVelocity()` 确保攻击时敌人停止移动。
- **状态退出**：检查 `triggerCalled` 变量，若为 true 则切换回 `skeleton.battleState`；同时在 `Exit` 中记录 `lastTimeAttacked = Time.time`，作为攻击冷却的起点。

### 4. 重构 EnemySkeleton 类
为了让状态机能访问到攻击状态，需要在 `EnemySkeleton` 类中进行声明和初始化。
1. **函数更名**：原有的 `ZeroVelocity` 已更名为 `SetZeroVelocity`（针对零速度的情况），以提高代码可读性，本文统一使用新名称。
2. **声明状态**：添加 `public SkeletonAttackState attackState { get; private set; }`；`battleState` 在 051 节已经声明（注意状态类名统一为 `SkeletonBattleState`，而非 `EnemyBattleState`）。
3. **初始化**：使用基类已经创建好的 `stateMachine`，再用**三参构造**实例化攻击状态，例如 `attackState = new SkeletonAttackState(this, stateMachine, "attack");`。

![代码实现](../screenshots/052_new3.jpg)

### 5. 实现动画触发机制（双层转发）
为了让攻击状态在动画播放完后自动结束，需要建立 `AnimationFinishTrigger` 的**双层转发机制**：

> 动画事件（Animation Event）→ 第一层 `EnemySkeletonAnimationTriggers.AnimationFinishTrigger()` → 第二层 `Entity.AnimationTrigger()` → 当前状态的 `AnimationFinishTrigger()` → `triggerCalled = true`

1. 在 `EnemyState` 基类中添加虚函数 `AnimationFinishTrigger()`，用于将 `triggerCalled` 设为 `true`（转发的终点）。
2. 创建 `EnemySkeletonAnimationTriggers.cs` 脚本并挂在动画子物体上，接收动画事件后转发给实体（第一层）。
3. 在 `Entity` 中提供 `AnimationTrigger()` 方法，把事件转交给状态机中**当前激活的状态**（第二层）。也就是说，`triggerCalled` 是由 Animation Event 经 `Entity.AnimationTrigger()` 置位的。

### 6. 配置攻击冷却，防止无限连击
如果只判断 `triggerCalled`，敌人打完一拳会立刻再次进入攻击状态，形成无限连击，因此需要一条完整的冷却链：
1. 在 `Enemy` 中添加字段：`[SerializeField] public float attackCooldown = 0.4f`、`[SerializeField] public float attackRadius = 2f`（可在 Inspector 中微调）和 `[HideInInspector] public float lastTimeAttacked`。
2. 在 `SkeletonAttackState.Exit` 中记录 `lastTimeAttacked = Time.time`。
3. 在 `SkeletonBattleState.CanAttack()` 中校验 `Time.time >= skeleton.lastTimeAttacked + skeleton.attackCooldown`；`Update` 里只有 `CanAttack()` 成立**且**与玩家距离小于 `attackRadius` 时才 `ChangeState(skeleton.attackState)`，否则保持战斗待机。

### SkeletonAttackState.cs
```csharp
using UnityEngine;

public class SkeletonAttackState : EnemyState
{
    private readonly EnemySkeleton skeleton;

    // 统一的三参构造：敌人本体、状态机、Animator 中的布尔参数名
    public SkeletonAttackState(Enemy _enemy, EnemyStateMachine _stateMachine, string _animBoolName) : base(_enemy, _stateMachine, _animBoolName)
    {
        skeleton = (EnemySkeleton)_enemy;
    }

    public override void Enter()
    {
        // 触发Animator中的attack参数
        base.Enter();
    }

    public override void Update()
    {
        // 攻击时停止移动（原 ZeroVelocity 已更名为 SetZeroVelocity）
        base.Update();
        skeleton.SetZeroVelocity();

        // 动画事件已经双层转发把 triggerCalled 置位，则返回战斗状态
        if (triggerCalled)
        {
            stateMachine.ChangeState(skeleton.battleState);
        }
    }

    public override void Exit()
    {
        base.Exit();

        // 记录本次攻击的时间，供 SkeletonBattleState.CanAttack() 计算冷却
        skeleton.lastTimeAttacked = Time.time;
    }
}
```

### SkeletonBattleState.cs (部分修改)
```csharp
public class SkeletonBattleState : EnemyState
{
    private readonly EnemySkeleton skeleton;
    private readonly Transform player;

    public SkeletonBattleState(Enemy _enemy, EnemyStateMachine _stateMachine, string _animBoolName)
        : base(_enemy, _stateMachine, _animBoolName)
    {
        skeleton = (EnemySkeleton)_enemy;
        player = PlayerManager.instance != null && PlayerManager.instance.player != null
            ? PlayerManager.instance.player.transform
            : null;
    }

    // 冷却是否结束：当前时间 >= 上次攻击时间 + 冷却时长
    public bool CanAttack()
    {
        return Time.time >= skeleton.lastTimeAttacked + skeleton.attackCooldown;
    }

    public override void Update()
    {
        base.Update();

        // 只有“冷却结束”且“玩家仍在攻击半径内”才进入攻击状态，
        // 否则敌人会贴着玩家无限连击
        if (player != null && CanAttack() &&
            Vector2.Distance(player.position, skeleton.transform.position) < skeleton.attackRadius)
        {
            stateMachine.ChangeState(skeleton.attackState);
        }
        else
        {
            skeleton.SetZeroVelocity();
        }
    }
}
```

## 📝 核心要点
- **状态隔离**：攻击状态通过 `SetZeroVelocity` 强制覆盖移动逻辑，防止敌人边走边打。
- **解耦触发**：使用 `AnimationFinishTrigger` 双层转发模式（动画事件 → `EnemySkeletonAnimationTriggers` → `Entity.AnimationTrigger()` → 当前状态），使代码不需要在 `Update` 中通过计时器判断动画是否结束，而是由动画事件驱动。
- **攻击冷却**：`Exit` 记录 `lastTimeAttacked = Time.time`；`CanAttack()` 校验 `Time.time >= lastTimeAttacked + attackCooldown`；叠加与玩家的距离 `< attackRadius` 判定后才切换攻击状态，彻底杜绝贴脸无限连击。
- **构造规范**：所有状态类统一使用三参构造 `(Enemy, EnemyStateMachine, string)` 并通过 `base(...)` 透传，便于基类统一持有状态机与动画参数名。
- **状态机流转**：`BattleState` $\xrightarrow{冷却完成且距离达标}$ `AttackState` $\xrightarrow{动画结束(triggerCalled)}$ `BattleState`。
