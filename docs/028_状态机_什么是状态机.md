## 🎯 本节目标
本节旨在让学习者理解**状态机 (State Machine)** 的核心概念、运作逻辑及其在游戏开发中的实际应用场景。本节为理论讲解，暂不涉及具体代码编写。

## 🖥️ 操作步骤

### 1. 理解状态机的基本定义
状态机是一种设计模式，它允许一个对象在不同的“状态”之间切换。每个状态代表对象的一种特定情况，而状态之间的切换则依赖于特定的“条件”。

**核心逻辑：**
- **状态 (State)**：对象当前所处的情况（例如：红灯、绿灯）。
- **条件 (Condition/Transition)**：触发状态切换的因素（例如：定时器到时、玩家按下按键）。

![交通灯状态机示例](../screenshots/028_new1.jpg)

### 2. 实际案例分析：任务系统 (Quest System)
在 RPG 游戏中，任务状态机确保了逻辑的线性执行，防止出现“跳关”现象。

- **状态流转**：`Available (可用)` $\rightarrow$ `Accepted (已接受)` $\rightarrow$ `Completed (已完成)`。
- **约束条件**：任务必须先处于 `Available` 状态才能被 `Accept`；必须先被 `Accept` 才能进入 `Completed` 状态。
- **状态行为**：
    - `Available`：角色头顶显示感叹号。
    - `Accepted`：屏幕右侧显示任务清单。
    - `Completed`：触发奖励发放逻辑。

### 3. 实际案例分析：角色行为控制
角色状态机通过限制状态间的转换，来增强游戏的控制感和灵活性。

![角色状态机逻辑](../screenshots/028_new2.jpg)

- **独立性**：当角色处于 `Attack (攻击)` 状态时，可以通过逻辑禁止其进入 `Jump (跳跃)` 状态。
- **输入驱动**：在 `Idle (待机)` 状态下监听 `Input` $\rightarrow$ 按下攻击键 $\rightarrow$ 切换至 `Attack` $\rightarrow$ 播放动画并造成伤害 $\rightarrow$ 自动返回 `Idle`。
- **优势**：由于各状态相互独立，修改攻击逻辑不会影响到待机或跳跃逻辑。

### 4. 进阶案例：复杂角色状态机
在实际开发中，状态机往往包含“子状态”和复杂的转移条件。

![复杂状态机图解](../screenshots/028_new3.jpg)

- **Ground State (地面状态)**：包含 `Idle` 和 `Move` 两个子状态，通过 X 轴 `Input` 在两者间切换。
- **Air State (空中状态)**：当检测到 `not as grounded`（不在地面）时进入。在此状态下，可能禁止攻击。
- **Wall Slide (墙壁下滑)**：从 `Air State` 接触墙壁进入。
    - 条件 A：检测不到墙壁 $\rightarrow$ 返回 `Air State`。
    - 条件 B：触发 `Jump Input` $\rightarrow$ 进入 `Wall Jump` $\rightarrow$ 返回 `Air State`。
    - 条件 C：触碰地面 $\rightarrow$ 直接返回 `Ground State`。

## 📝 核心要点

| 概念 | 说明 |
| :--- | :--- |
| **状态 (State)** | 对象的一种特定情况（如 `Idle`, `Jump`, `Attack`）。 |
| **转移 (Transition)** | 从一个状态切换到另一个状态的过程。 |
| **条件 (Condition)** | 触发转移的因素（如 `Input`, `Timer`, `Collision`）。 |
| **独立性 (Independence)** | 每个状态的逻辑是隔离的，修改 A 状态不会破坏 B 状态。 |
| **灵活性 (Flexibility)** | 通过定义转移路径，可以精准控制角色在什么情况下能做什么。 |
